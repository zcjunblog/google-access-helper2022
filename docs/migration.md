# 迁移与排错指南

文档核查日期：**2026-10-26**。本指南帮助区分平台兼容问题、代理配置问题和第三方服务问题。

本仓库当前版本已经提供可直接加载的 MV3 扩展，安装与使用见 [安装指南](install.md)。

## 先确认你遇到哪一种问题

| 现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 提示 Manifest V2 已弃用、版本不受支持或无法加载 | 扩展的 `manifest_version` 与当前浏览器支持情况 | 查阅作者兼容说明，选择 [当前工具入口](alternatives.md) 中适用的工具 |
| 扩展已安装，但浏览器仍无法访问 | 当前生效的代理配置、其他扩展是否控制代理、服务地址和端口 | 先只保留一个代理配置扩展生效，再分别核对配置与服务 |
| 扩展能打开，但注册、登录或获取线路失败 | 上游账号系统和服务状态 | 查上游公告；本仓库不能恢复第三方注册或账号服务 |
| 切换扩展后代理状态异常 | 旧配置、系统代理和扩展之间的控制关系 | 导出配置，停用冲突扩展，重新选择明确的配置后再验证 |

## 为什么原来的安装方法失效了

使用 Manifest V2 的扩展已不适用于当前 Chrome。根据 [Chrome 官方时间线](https://developer.chrome.com/docs/extensions/develop/migrate/mv2-deprecation-timeline)，Chrome 139 及后续版本不再支持 MV2；2026-08-31，剩余 MV2 扩展也从 Chrome 商店移除。

因此，“开启开发者模式 → 加载已解压扩展 → 重启浏览器”不能作为当前 Chrome 的有效解决方案。原 manifest 中的 `minimum_chrome_version` 只是历史最低版本声明，不会覆盖 MV2 的停用规则。

该结论针对 Chrome。其他 Chromium 浏览器和 Firefox 的政策需要分别核实，不能仅因内核相近就推断可用。

## 建议迁移步骤

1. **记录现状。** 记录浏览器名称与完整版本、扩展目录、错误文本及发生步骤；保存需要的配置。不要在公开 Issue 中粘贴账号、密码或完整订阅链接。
2. **确认扩展职责。** 代理管理扩展负责配置，实际联网仍取决于你使用的代理服务。旧插件附带的第三方服务不会随更换扩展自动迁移。
3. **选择当前工具。** 从 [资源目录](alternatives.md) 打开官方商店或作者发布页，查看最新说明。
4. **逐项迁移配置。** 只有上游明确支持的格式才进行导入；不同扩展的设置文件不一定通用。也可以手动重新填写已有代理信息。
5. **验证结果。** 分别确认扩展能加载、配置能保存、代理服务器可达，以及目标网页能访问；每一步的成功都不代表后续步骤一定成功。

## 为什么不能直接把 `2` 改成 `3`

MV3 涉及后台生命周期、权限和请求处理方式变化。对 MV2 插件做真正迁移，至少需要检查以下内容：

| 范围 | 需要评估的变化 |
| --- | --- |
| 后台运行 | 后台页面 / 常驻脚本迁移为 service worker 后，不能继续假设 DOM 和内存状态长期存在 |
| 扩展入口 | `browser_action` 等旧字段需要按新 manifest 结构调整 |
| 主机访问 | 梳理 API 权限、`host_permissions` 和可选权限 |
| 网络请求 | 逐项评估 `webRequestBlocking` 的用途及当前允许的替代方案，不能机械替换 |
| 脚本与 CSP | 检查远程脚本、动态执行与内容安全策略是否满足 MV3 要求 |
| 服务依赖 | 单独验证注册、登录、线路接口和认证协议，前端迁移不会自动修复服务端 |
| 来源与许可 | 核对第三方代码及依赖的修改和再分发条件 |

参考 [MV3 概览](https://developer.chrome.com/docs/extensions/develop/migrate/what-is-mv3) 与 [官方迁移文档](https://developer.chrome.com/docs/extensions/develop/migrate)。本仓库的 MV3 扩展为新的独立实现，第三方项目的开发与发布由对应维护者负责。

## 如何提交有效反馈

使用仓库的兼容性反馈模板，提供浏览器版本、工具名称、复现步骤和已脱敏的错误信息。资源入口失效或版本信息过期，请使用资源更新模板，附上作者官方来源和核查日期。
